# 权限管理升级 Demo · 需求说明

> 本文件是分步开发的共同参考，请放到项目里（建议路径 `docs/permission-demo-spec.md`）。每一步的提示词会指明要读哪几节。

## 0. 你要做什么

在现有的管理端 Demo 项目里（本地访问 `http://localhost:8765/panorama.html`），增加权限管理升级（V2.1）的新功能页面，用于给校方和团队演示、收集反馈。**不新建独立工程**，在这个项目里新增页面。**现有页面 `panorama.html`、`kmap.html` 一个字节都不改**，演示从新页面 `system.html` 进入。

- **不做登录。** 用顶部的「演示身份」切换不同账号（见第 4 节）。
- 核心演示点：**同一套页面，切换不同演示身份后，看到的菜单、按钮、数据、脱敏结果都不一样，并且和规则一致。**
- 需求依据：《AIGC智慧教学平台_权限管理升级方案_V2.1_开发交付版.docx》（我会放在项目里 / 附在对话中）。**业务规则以该文档为准**，本文件是它的 Demo 化摘要；两者冲突时以文档为准，并把冲突点记进说明文档。**不要自行发明业务规则**：文档没写到的地方，页面上用灰色小字标「Demo 占位」，并记进说明文档。

## 1. 现有项目情况（先读代码核实）

- 纯静态 HTML Demo，不用前端框架。每个页面是一个独立的 `.html` 文件，样式和脚本内联在页面里：
  - `panorama.html`：行业分析（能力全景），体积很大，内联了行业数据；
  - `kmap.html`：行业图谱。
- 页面之间通过左侧栏 `<aside class="lnav">` 跳转。当前侧栏结构：
  - 概览：数据概览（空）/ 行业分析 / 行业图谱
  - 教务：教务基础数据（空）/ 课程计划管理（空）/ 账号与角色（空）
  - 系统：系统配置（空）
  - 「空」的菜单目前是 `<button class="lmenu">`，没有链接。
- 视觉：紫罗兰品牌色、浅紫背景、白色窄侧栏、白色卡片。新页面直接复用现有页面的 CSS 变量、类名和组件写法（侧栏、页头、tab、卡片、表格、按钮、标签），做到和 `panorama.html`、`kmap.html` 看起来是同一个产品。

动手前先阅读这两个页面的结构和样式，在实现计划里说明：准备复用哪些样式和组件，新文件放在哪里。

## 2. 工程约束

- **不修改现有页面。** `panorama.html`、`kmap.html` 一个字节都不改，里面的空菜单保持原样。新页面侧栏里的「行业分析」「行业图谱」单向链接到这两个原有页面。
- 新页面沿用现有写法：每个页面一个 `.html`。多个页面共用的东西抽成独立文件，例如：
  - 公共样式：参照现有页面的侧栏、页头、卡片、表格等写法，复制到新的公共样式文件里供新页面引用（只读取、不修改原文件）；
  - 侧栏：所有新页面用同一份菜单配置渲染，菜单按当前演示身份的权限显示或隐藏；
  - mock 数据和权限模块：独立的 `.js` 文件。
- 所有权限判断写在**一个独立的纯函数模块**里（例如 `js/permission.js`），页面只调用它，不在页面里写散落的 if。用 Node 自带的测试工具为它写单元测试，覆盖第 8 节的全部 D 用例。
- 权限点、角色模板、脱敏规则都写成**配置数据**，不要硬编码在页面里。
- 演示中的数据改动（分配角色、共享、发布、审计日志等）要能**跨页面保留**（例如存在浏览器本地存储），提供「重置演示数据」按钮恢复初始状态。

## 4. 全局：演示身份条

所有**新页面**顶部固定一条浅色的演示身份条（现有的 `panorama.html`、`kmap.html` 不加）：

- **「当前身份」下拉**：切换第 6 节的演示身份。切换后菜单、页面数据、按钮立刻按新身份刷新，并且自动跳到该身份可见的第一个页面。
- **「当前组织」下拉**：这是**视图过滤，不是权限**。
  - 权限始终是各条分配范围的并集，切换下拉不增加、不减少任何权限；
  - 默认值为「全部授权范围」（即并集）；可选项是授权范围内的节点及其下级，用树形选择；一人多角色时，取所有带组织节点的分配的并集；
  - 选中某个节点时，数据列表只显示该节点及其下级；新增数据时「所属组织」默认填为当前组织，可在授权范围内修改；
  - 菜单由角色决定，**不随当前组织变化**；
  - 年级筛选照常生效，不受当前组织影响；
  - 没有组织节点范围的身份（教师、班主任、学生、企业导师）不显示这个下拉；
  - 切换不写审计日志；选择跨页面保留，切换演示身份时重置为「全部授权范围」。
- **「为什么能看到 / 看不到」开关**：打开后，列表每行和每个被隐藏的按钮旁会出现一个小问号，悬停时显示判定过程：命中哪条角色分配 → 功能权限是否通过 → 范围是否通过 → 用的是哪一档脱敏规则。这是演示时最有说服力的部分，必须做。
  - 打开开关时，列表底部额外列出「被当前组织过滤」的条数，点开可看到这些数据，并标注「有权限，被当前组织过滤」，与「无权限」明确区分。
- 根据演示身份所属的端，跳转到该身份可见的第一个新页面。新页面侧栏中的「行业分析」「行业图谱」对所有管理端身份显示，点进去是原有页面。
- 提供「重置演示数据」按钮，把 mock 数据恢复为初始状态。

## 7. 页面与功能

### 7.1 组织管理（系统配置 › 组织管理）

- 左侧是组织树（可展开、可搜索），右侧是节点详情。
- 节点字段：名称、编码、组织类型（取自字典）、上级节点、排序、状态、说明。
- 操作：新增下级、编辑、移动（改上级）、停用 / 启用、删除。
- 规则：
  - 根节点唯一，不能删除、不能移动。
  - 层级**不设上限**。
  - 同一上级下名称不能重复；编码全局唯一。
  - 平台超级管理员可以维护整棵树；组织管理员只能看到并操作**本节点的下级**，本节点及其上级只读。
  - 节点下仍有子节点、挂载专业、所属账号，或被角色范围引用时，**不能删除**。弹窗列出阻塞删除的对象。
  - 移动节点时，下级节点和挂载的专业一起移动。
  - 停用后，该节点不再出现在「数据范围」「所属组织」的选择框里；已有授权保持有效，在角色分配处显示「节点已停用」标签。
  - 以上每个操作都写一条审计日志。
- **新增节点与管理员：**
  - 新增节点不生成新角色，不自动指定组织管理员；未指定时由上级节点的组织管理员和平台超级管理员管理。
  - 新增保存成功后弹窗：「「xxx」已创建，目前由上级组织管理员管理。是否现在为该组织指定组织管理员？」按钮：稍后指定 / 去指定。
  - 点「去指定」：打开「选择账号」弹窗，可按姓名、账号搜索；只列出当前身份范围内、启用状态的教职工账号，不列出本人。选中后跳到账号与角色页，打开该账号的编辑，自动新增一张角色分配卡片，预填「组织管理员 + 新节点」，可修改；点「保存」后才生效，保存时照常做授权约束校验。
  - 点「稍后指定」：关闭弹窗，不做任何分配。
  - 右侧详情新增「本节点组织管理员」：显示角色分配节点**正好是本节点**的组织管理员姓名，挂在上级节点的不列出；没有时显示「未指定（由上级组织管理员管理）」，旁边有「指定管理员」按钮，流程同「去指定」。

### 7.2 字典管理 › 组织类型

- 平台已有通用的「字典管理」，目前只有字典「专业」；本期在其中新增字典「组织类型」。Demo 里字典管理页只需做「组织类型」，「专业」字典显示为一个灰色占位项，标「现有字典，Demo 不演示」。
- 可增删改、停用组织类型。被节点引用的类型不能删除，提示「该类型已被 N 个组织节点使用，不能删除。」
- 维护权限（字典全校共用，归属根节点）：

| 身份 | 权限 |
|---|---|
| 平台超级管理员 | 新增、编辑、停用、删除 |
| 组织管理员（分配中含根节点，如张校管） | 新增、编辑、停用、删除 |
| 组织管理员（只挂下级节点，如刘院管、陈双管） | 可进入查看，没有新增、编辑、停用、删除按钮；新增组织节点时可以选类型 |
| 其他身份（含周教务、吴学工、郑督导、钱信息） | 看不到「组织类型」字典；直接访问被拒绝，并写审计日志 |

- 权限点按字典单独配置：「系统配置 : 组织类型 : 查看 / 新增 / 编辑 / 停用 / 删除」。
- 新增、编辑、停用、删除都写审计日志。

### 7.3 专业管理（教务基础数据）

- 新增必填列和字段「所属组织」，只能选择启用中的节点。班级列表显示「所属组织（随专业）」。
- 列表和详情新增只读列「专业负责人」：显示角色分配中「专业负责人 + 本专业」的全部人员，多人用顿号分隔；没有时显示「未指定」。
- 专业负责人**不是必填项**；一个专业可以有多名负责人，权限相同。未指定负责人时，专业内容由所属组织的组织管理员和教务维护。
- 新增专业保存成功后：
  - 当前身份有角色分配权限（超管、组织管理员）时弹窗：「专业「xxx」已创建。是否现在指定专业负责人？专业负责人可以稍后在账号管理中指定。」按钮：稍后指定 / 去指定。「去指定」的流程同 7.1，预填卡片为「专业负责人 + 新专业」。
  - 当前身份没有角色分配权限时，只提示「保存成功」。
- 专业详情的「专业负责人」旁有「添加负责人」按钮（只对有角色分配权限的身份显示），流程同「去指定」；已有负责人时仍可继续添加。

### 7.4 账号管理（账号与角色）

- 列表新增「所属组织」「角色（可多个 tag）」「状态（在读 / 已毕业 / 停用）」三列。列表本身也按当前身份的范围过滤。
- 编辑账号时，角色改为**多条角色分配**，每条分配是一张卡片，包含：
  - 角色（下拉，按类型分组：内置 / 预设 / 部门模板 / 自定义）；
  - 数据范围：组织树多选，每个选中的节点可以再选一个或多个年级（不选 = 全部年级）。班主任这一项改为直接选班级；
    - 教务、学工、督导：组织节点默认选中根节点，可改为一个或多个下级节点；操作人范围不含根节点时不预选；
    - 督导：不显示年级；
    - 信息中心：不显示组织节点，固定全校；
  - 教学范围（仅教师类角色）：在组织树下展开到 专业 → 班级 + 课程，多选；
  - AI 每日配额：只读显示，值来自角色。
- 保存时做授权约束校验，不满足就拦截并给出原因：
  - 不能给自己分配角色；
  - 授出的节点、年级、班级不能超出操作人自身的范围；
  - 教学范围只能由「班级所在组织」的组织管理员，或作用域覆盖该班级的教务授予。
- 账号停用后，其全部角色分配和教学范围同时失效：该账号在任何页面的判定都不通过；角色分配卡片显示「账号已停用，分配已失效」。

### 7.5 角色管理（账号与角色）

- 角色列表按类型分组：内置 / 预设 / 部门模板 / 自定义。
- 权限点树细化到**操作级**：模块 → 页面 → 操作（查看 / 编辑 / 审核发布 / 删除等）。
- 只有平台超级管理员能看到并进入角色管理；其他身份看不到这个 tab。

### 7.6 学生信息（教务基础数据）

这一页用来集中演示**范围 + 年级 + 脱敏 + 毕业**：

- 列表：姓名、学号、班级、年级、手机号、身份证号、家庭住址、状态。点击某个学生可以看成绩。
- 数据按当前身份的范围过滤（组织节点 + 年级 / 指定班级 / 教学范围）。
- 敏感字段按 7.10 的脱敏表展示；每次查看明文都写审计日志。
- 已毕业学生所在的行，对教师和管理员只读，没有编辑按钮。

### 7.7 教师档案（教师端）

默认显示本人档案；有范围的身份可以通过「切换教师」查看他人的教师档案：组织管理员看本范围，督导看全校，教师只看本人。**年级筛选对教师档案不生效。**

### 7.8 教师端 › 备课中心 › 我的资源 / 共享给我的 / 校本资源库

**我的资源**

- 每份资源有一个「共享」按钮，弹窗里可以选择：
  - 指定教师（全校教师可搜，不受组织限制）；
  - 指定组织节点（含下级）；
  - 「推荐到校本资源库」。
- 已共享的资源可以撤回。
- 「学情分析」类资源**没有共享按钮**。

**共享给我的**

- 只能「查看」和「复制到我的资源」。复制出的副本归接收人，可以编辑；原件只读。
- 作者撤回后，原件从这里消失，已复制的副本保留。

**校本资源库**

- 全校教师可以查看、复制已发布的内容。
- 组织管理员（范围覆盖作者）和教务可以看到「待发布」标签页，执行「发布」或「不发布」。
- 组织管理员、教务和作者可以撤下已发布的内容。
- 推荐后、发布前，其他教师看不到这份内容。

以上共享、撤回、推荐、发布、撤下、复制操作，都写审计日志。

### 7.9 审计日志（系统配置）

列：时间、操作人、操作类型、对象、操作前、操作后、结果（成功 / 被拒绝）。越权尝试（例如通过「为什么看不到」去点隐藏的操作）也要以「被拒绝」记录。按当前身份的范围过滤。

### 7.10 判定规则（实现在权限模块里）

**每次访问按三步判定：**

1. **功能权限**：当前身份的任一条角色分配是否包含这个权限点。
2. **范围**：只用**包含该权限点的那条分配**的范围来判断，不能拿 A 分配的功能配 B 分配的范围。
   - 管理类数据（账号、专业、教师档案、基地、组织节点）：数据所属组织是否在「所选节点及其全部下级」内。
   - 带年级属性的数据（班级、学生、作业、成绩、实习）：在节点判断的基础上，再叠加年级筛选。
   - 教学类数据：
     - 教师类角色（教师、专业负责人、企业导师）：本人创建的，或者在教学范围内（企业导师为本基地课）；
     - 管理类角色（组织管理员、教务、学工、督导、班主任、辅导员）：按数据的归属组织判断，即教学类数据关联的「班级 → 专业 → 所属组织」落在这条分配的范围内即可见。
   - 班主任：指定班级；企业导师：本基地。
   - **部门条线**（教务、学工、督导）不是单独的范围类型：能看哪类数据由权限点决定，能看学校的哪一部分由这条分配选的组织节点决定，两者同时满足才可见。教务、学工可附加年级，督导不附加年级。信息中心不选范围，固定全校，且只涉及账号与系统配置。
3. **脱敏**：按下表展示。

用户最终的权限 = 各条分配「功能 × 范围」的并集。

### 7.11 内容审核（教务基础数据，占位）

只用来演示「谁有审核按钮」，不做真实的审核业务：

- 列出 5～6 条待审内容（课程内容、教材、人培方案各几条），每条带所属组织。
- 「通过 / 退回」按钮按矩阵中「M2 / M3 / M4 审核发布」判定：范围覆盖该内容的组织管理员、教务有按钮；督导、教师等没有。
