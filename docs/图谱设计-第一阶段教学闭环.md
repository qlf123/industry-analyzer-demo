# 图谱设计 · 第一阶段教学闭环（兼容整体规划 v1.0）

> 2026-11-12 · 在现有原型图谱（行业能力图谱 / 专业知识体系 / 全景图谱 + 版本 + 子图）基础上设计，目标：**支撑第一阶段教学闭环（PRD 8 批次）先行落地，关系命名与分层直接对齐《岗课赛证一体化平台·全链路数据图谱设计》v1.0，后续扩展不做返工。**

---

## 一、设计原则（继承规划，做第一阶段裁剪）

| # | 原则 | 第一阶段裁剪 |
|---|---|---|
| P1 | 结构进图库，事务进关系库 | **严格执行**：排课/发布/评价/证据/达成全部事务侧，图谱零事务数据 |
| P2 | 能力点是全平台主键 | **分两步走**：第一阶段闭环枢纽是「技能」（备课/发布/证据/达成/补训都挂技能）；能力点经「已确认映射」与技能相连，承担测评与覆盖率。**不合并、不改名**，映射即桥（见 §五） |
| P3 | 关系承载语义，不建中间表 | 第一阶段边类型只建 9 种（§四），但**命名全部采用规划关系名**，预留边类型只注册不建数据 |
| P4 | 版本与留痕内建，发布即快照 | 沿用原型语义：发布单元=专业、manifest 记来源版本、已发布只读、回滚不回退来源 |
| P5 | 按专业物理隔离 | 沿用：复合标签（正式环境 `:Skill:Guide`），跨专业不共享节点 |

## 二、图谱分层模型（什么进图、什么不进）

```
┌─ L1 标准层（只读输入）  岗位标准 / 1+X证书 / 赛项标准 ── 第一阶段：mock，不建
├─ L2 结构层（图谱本体）  岗位·能力项·技能·知识点·课程·任务·赛项·证书节点 + 结构关系 ── 建图，随版本
├─ L3 内容层（挂载展示）  备课资源 / 知识库资料 / 课件挂到技能节点 ── 展示层叠加，不随版本
├─ L4 事务层（关系库）    课程计划/排课/任务/提交/评价/证据/达成 ── 不建图（PG）
└─ L5 快照层（只读回流）  掌握度当前值 / 覆盖缺口 / 课程技能覆盖 ── 异步同步上图，只读
```

**判定口诀**：会随评价反复变的→L4；随资源增删变的→L3；只在人工修订/审核发布时变的→L2。任何 L4 数据要上图，只允许走 L5 快照通道。

## 四、关系模型（第一阶段 9 种边 + 预留清单）

**第一阶段建的边（命名 = 规划关系名，兼容零成本）：**

| 关系 | 含义 | 第一阶段作用 | 属性 |
|---|---|---|---|
| `REQUIRES` | 岗位→能力项 | 测评覆盖率、能力地图 | level(L1–L3)、weight |
| `MAPS_TO` | 能力项→技能（即原型"已确认映射"） | **两枢纽之桥**：技能达成聚合到能力达成 | weight、type(直接/部分)、status(已审核/已调整——待审核不建边) |
| `CONTAINS` | 课程→任务→技能→知识点 | 知识树、发布时按技能带知识点 | order |
| `SUPPORTS` | 课程→能力项（**新增推导边**） | 课程技能覆盖统计、规划覆盖率口径（四向都有连接的 Ability / 总数） | 由 MAPS_TO 聚合推导，可重算 |
| `MOUNTED_ON` | 备课资源→技能（**新增**） | 带入备课反向定位、子图"找资源"、资源悬挂检测 | kind(课件/教案/视频…) |
| `SUBMITTED_BY` | 老师补充节点→提交人 | 教研贡献署名 | submittedAt、status |
| `SNAPSHOT_OF` | GraphVersion→节点集合 | 版本回滚、历史追溯 | manifest(各来源版本号) |
| `PRE_REQUIRES` | 知识点→知识点 前置 | **预留建边**（第一阶段仅注册）；规划驱动学习路径与断链检测 | — |
| `SAFETY_CONSTRAINT` | 知识点约束实操 | **预留建边**；规划硬门禁："被约束知识未达标时实操任务被发布接口拦截"——第一阶段发布接口预留校验钩子 | — |

**只注册不建数据（后续批次解锁）**：`ASSEMBLED_FROM`（任务由能力点组装）、`EVIDENCE_FOR`、`HAS_MASTERY`（第一阶段以 L5 快照形式只读展示）、`GAPS_ON`、`EXPLAINS`、`CONFUSES_WITH`、`PARALLEL`、`SUB_ABILITY`、`HAS_LEVEL`、`MEASURED_BY`、`ASSIGNS`、`IMPLEMENTS`、`AFFECTS`。

## 五、关键兼容决策：技能与能力点双枢纽

规划要求能力点唯一主键；第一阶段闭环实际跑在技能层。设计裁定：

```
备课/发布/证据/达成/补训  ──跑在──▶  技能 Skill          （教学闭环枢纽）
岗位/测评/覆盖率/画像    ──跑在──▶  能力项 Ability      （标准主键）
                    └── MAPS_TO（已审核）──┘
```

- 发布任务只允许勾选**技能**及其知识点（快照 `skillIds/kpIds/kpSnap`），学情按技能/知识点统计——第一阶段不变；
- 测评（专业建设测评）按能力项统计，数据来自 MAPS_TO 聚合技能达成——口径已在 `teacher-kit.js kn().map` 实现（只用已审核/已调整+计入类型），正式化即 MAPS_TO 边的 status 过滤；
- 后续规划全面落地时，`ASSEMBLED_FROM` 等边挂在能力点上，教学闭环数据通过技能→能力项反向可达，**不需要迁移闭环数据**。

## 六、教学闭环 8 环节 · 图谱读写点

| PRD 批次 | 环节 | 读图谱 | 写图谱 | 版本影响 |
|---|---|---|---|---|
| 批1 | 课程与排课 | 课程→技能可达路径（判定课程是否"已关联"） | 无 | 无 |
| 批2 | 知识体系关联 / 标准反哺 | 课程节点、技能库 | 课程↔体系关联；老师补充→建议审核→并入标准图谱 | 反哺并入=来源发版→全景同步草稿→发布 |
| 批3 | 智慧课堂框架 | 无（展示当前发布版本） | 无 | 读当前版本 |
| 批4 | 备课 | 能力地图树、技能/知识点定义；资源 MOUNTED_ON 反向带入 | 资源挂载关系（L3，实时） | 不随版本 |
| 批5 | 发布/作答/评价 | 按技能带知识点（CONTAINS）；判定依据默认取知识点 core | 任务快照 `skillIds/kpIds/kpSnap` → **事务侧** | 发布即任务级快照；图谱版本无关 |
| 批6 | 学情与改进 | 展示层：技能节点带掌握度颜色（L5 快照）；覆盖缺口 → 补训 | 无直接写；缺口发起补训回到批4/5 | 快照异步刷新 |
| 批7 | 管理端测评 | REQUIRES+MAPS_TO 聚合能力达成、覆盖率 | 无 | 读当前发布版本 manifest |
| 全景 | 同步/发布/回滚 | 来源版本 diff | GraphVersion 新版本（SNAPSHOT_OF） | 版本中枢 |

**闭环对图谱的唯一硬依赖**：技能/知识点的**已发布版本定义**（名称/类型/core）——发布任务时快照固化，之后图谱修订不影响在评任务。这条已实现，正式化时对应规划"任务 v1.3 引用图谱 v2"的阶段版本串接。

## 七、版本与子图（沿用原型语义，正式化要点）

1. **GraphVersion**：每专业一份，`{cur, draft?, versions[{v, time, by, manifest{ag,ks,comp,cert}, sum, note}]}`——原型 `pano_version_v2` 结构直接迁移 PG；Neo4j 存 `SNAPSHOT_OF` 边供路径查询，快照本体存对象存储（object_key）。
2. **草稿与影响分析**：同步来源新版本 → diff（节点停用→关系失效、等级变化→待复核、改名→保留）→ 合并进草稿（单草稿）→ 两级校验（覆盖率阈值/孤立节点/能力点无知识点阻止发布）→ 发布。对应规划 ImpactRecord + 六条自检清单。
3. **子图**：规则型（起点+链路+筛选），实时取数；默认跟随当前发布版本，可锁版本（漂移提示）；场景模板按「来源已有已发布版本」自动判定 ready——赛项/证书入图后备赛/考证/岗位三个模板自动解锁，无需改代码。

## 八、落地路线（与 PRD 批次对齐）

| 里程碑 | 内容 | 对应批次 |
|---|---|---|
| M1（现在~批2） | L2 结构入图（岗位/能力项/技能/知识点/课程 + REQUIRES/MAPS_TO/CONTAINS）；版本服务承接 `pano_version_v2` 语义 | 批1、批2 |
| M2（批4~5） | `MOUNTED_ON` 资源挂载真实化（skillIds 回挂）；发布快照接口化；`SAFETY_CONSTRAINT` 校验钩子预埋（不启用） | 批4、批5 |
| M3（批6~7） | L5 快照通道（掌握度当前值上图只读、覆盖缺口）；`SUPPORTS` 推导边重算服务；测评口径切换 MAPS_TO 边过滤 | 批6、批7 |
| M4（第二阶段） | 赛项/证书标准库入图（`MAPS_TO` 考点/评分点）→ 三个场景子图解锁；`PRE_REQUIRES` 学习路径；`ASSEMBLED_FROM` 任务组装 | 规划 v1.0 全量 |

**约束**：M1–M3 期间不引入 Neo4j 也可跑（原型已证明前端合并可行），但关系命名、快照结构、状态机从第一天就按本设计落库字段命名，避免 M4 迁移返工。
