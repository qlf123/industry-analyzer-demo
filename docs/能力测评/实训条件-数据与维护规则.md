# 实训条件需求 · 数据与维护规则（开发用）

> 版本：2026-10-21 · 作者角色：产品
> 适用：知识体系平台（实训条件的生成与维护）、管理端【能力测评】（实训条件的使用）
> 关联：推导规则 `.claude/skills/training-condition-derivation/SKILL.md`；构建时如何提取 `docs/能力测评/知识体系构建-实训条件提取说明.md`；数据总表 `docs/能力测评/数据需求.md` 第 5A 节；导游专业草稿 `docs/能力测评/导游专业-实训条件草稿.xlsx`

---

## 1. 背景与目标

知识体系描述了「教什么」，但没有说明「在什么条件下教」。能力测评需要回答：**本校开设的课程需要哪些实训条件、本校具备多少、缺口影响哪些岗位能力**。

实训条件需求有两个来源：

1. **AI 生成**：知识体系构建时直接标注，或构建后按推导规则补齐；
2. **人工维护**：专家新增、修改、驳回。

本文规定这两类数据**如何存、如何合并、如何汇总、如何在测评中使用**，保证：AI 可以反复重新生成，**人工的结论永远不会被覆盖**。

### 不做的事

- 不从知识体系推导规格与数量（面积、工位数、台套数、配置标准）。
- **不显示没有出处的数字**：工位数、每工位人数等数量信息，只有在标准原文中有规定时才作为「建议」显示；没有标准依据的条件，页面和报告中**不出现任何数量、推算值或「工位不足」结论**。

### 准确性原则

页面和报告上呈现的每一项内容都必须能追溯到来源：字典条目、带依据的实训需求、学校填报的资源、或标准原文。无法追溯的内容不显示，不用默认值或估算值补位。
- 不把推导结果称为「标准要求」。页面与报告统一称「**实训需求**」；「符合 / 不符合标准」须另有标准原文数据，不在本文范围。

## 2. 名词

| 名词 | 定义 |
|---|---|
| 实训条件 | 教学所需的场地、模拟场景、设备耗材、软件或校外基地，如「急救技能训练器材」「口岸通关模拟场景」 |
| 条件字典 | 平台统一维护的实训条件清单。所有需求只能引用字典中的条件 |
| 实训需求 | 「某个教学对象需要某项实训条件」的一条记录 |
| 挂载对象 | 实训需求挂在哪里：**技能**（细粒度）或**课程**（整门课都需要） |
| 级别 | 必需：离开该条件，技能的动作无法完成或无法考核；建议：有则效果更好，普通教室也能完成 |
| 来源 | auto：AI 生成；manual：人工新增 |
| 状态 | 待审核 / 已审核 / 已调整 / 驳回 / 失效，见第 5 节 |

## 3. 数据实体

### 3.1 条件字典

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | 字符串 | ✓ | 编号，创建后不可修改，如 `EQ-AID` |
| name | 字符串 | ✓ | 名称，全字典唯一 |
| category | 枚举 | ✓ | 场地 / 场景 / 设备耗材 / 软件 / 校外基地 |
| spec | 文本 | ✓ | 功能要点：能支持开展什么教学活动。**不写数量**（数量只来自标准，见 3.4） |
| source | 文本 | ✓ | 来源说明，如「按课程内容推导」「人工新增」「原中职字典」 |
| status | 枚举 | ✓ | 启用 / 停用 |
| created_by / created_at / updated_by / updated_at | — | ✓ | 审计 |

**规则**

| # | 规则 |
|---|---|
| D1 | 新增：名称不能与已有条目（含停用的）重复；提示近似名称（编辑距离或包含关系），防止「急救器材」「急救训练器材」并存 |
| D2 | 修改：可改名称、功能要点、类别；id 不可改。改名后所有引用自动显示新名称 |
| D3 | 删除：**未被任何需求引用**时可删除；已被引用的只能停用 |
| D4 | 停用：停用后不能被新需求选用；已有需求保留，在列表中标「条件已停用」，**仍参与汇总**，直到需求被修改或驳回 |
| D5 | 合并：把条目 A 合并到 B 时，引用 A 的需求全部改为引用 B；若同一挂载对象已同时引用 A 和 B，保留级别较强的一条（必需 > 建议），另一条记为驳回，驳回理由「合并重复条件」。A 随后停用 |
| D6 | AI 只能从「启用」的条目中选择；AI 认为字典缺项时，输出「字典新增建议」进入待处理列表，**不自动建条目** |

### 3.2 实训需求

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | 字符串 | ✓ | 需求编号 |
| system_id | 字符串 | ✓ | 所属知识体系（专业） |
| target_type | 枚举 | ✓ | 技能 / 课程 |
| target_id | 字符串 | ✓ | 挂载节点 ID。**必须用节点 ID**，名称只作显示 |
| condition_id | 字符串 | ✓ | 引用字典条目 |
| level | 枚举 | ✓ | 必需 / 建议 |
| basis | 文本 | ✓ | 依据。AI：技能侧原文 + 为什么需要；人工：理由（必填，至少 5 个字） |
| source | 枚举 | ✓ | auto / manual |
| status | 枚举 | ✓ | 待审核 / 已审核 / 已调整 / 驳回 / 失效 |
| origin | 对象 | — | 仅「已调整」：调整前的 condition_id、level、basis，用于追溯 |
| reject_reason | 文本 | 条件 | 驳回时必填 |
| created_by / created_at / updated_by / updated_at | — | ✓ | 审计；AI 生成的 created_by 记生成任务编号 |

**唯一性**：同一 `(target_type, target_id, condition_id)` 只能有一条**有效**记录。有效 = 状态不是「驳回」「失效」。

### 3.3 本校实训资源（学校填报）

| 字段 | 必填 | 说明 |
|---|---|---|
| 名称 | ✓ | 如「导游服务综合实训室」 |
| 类型 | ✓ | 校内实训室 / 校外基地 |
| 具备条件 | ✓ | 多选字典条目（一个实训室可具备多项条件） |
| 工位数 / 可同时容纳人数 | 选填 | 仅当该条件有标准规定的数量时参与对照（见 3.4、8.1）；否则只作为登记信息展示 |
| 服务课程 | — | 本校课程，多选 |
| 合作单位、可承接岗位、年可接收人数、协议有效期 | 校外 ✓ | 校外基地专用 |
| 状态 | ✓ | 在用 / 停用；停用的不计入具备 |

### 3.4 数量标准（来自标准原文，按条件）

数量信息**不设默认值**，只从标准原文录入。

| 字段 | 必填 | 说明 |
|---|---|---|
| condition_id | ✓ | 对应字典条目 |
| 规定方式 | ✓ | 二选一：「每工位（组）人数」如每 2 人 1 工位；或「最少数量」如不少于 4 具 |
| 数值 | ✓ | 标准原文中的数值 |
| 适用范围 | — | 专业 / 层次（如高职导游专业） |
| 出处 | ✓ | 标准名称、发布机构、年份、条款号；不填出处不能保存 |
| 原文摘录 | ✓ | 原文句子，供核对 |

建议工位 / 台套数：
- 规定方式为「每工位人数」：⌈同时上课人数 ÷ 每工位人数⌉。同时上课人数由学校填写（一般取班额）；**学校未填写时不计算、不显示**。
- 规定方式为「最少数量」：直接取标准数值。

页面和报告中显示为「建议 y 个工位（依据：标准名称 条款号）」。

**没有数量标准的条件：不显示任何工位数、建议值或推算值，也不判「工位不足」。**

## 4. 两种挂载方式

| | 挂在技能上 | 挂在课程上 |
|---|---|---|
| 用途 | AI 生成的默认方式；专家对某个技能单独补充 | 人工快速录入「整门课都在某处上」，不必逐个技能标注 |
| 例子 | 「高质量胸外心脏按压」→ 急救技能训练器材，必需 | 《模拟导游》→ 导游服务综合实训室，必需 |
| AI 能否生成 | 能 | **不能**（只由人工创建） |
| 汇总到课程 | 进入课程汇总 | 直接进入课程汇总 |
| 汇总到能力 × 等级 | 沿「技能 → 能力」映射汇总 | 视为该课程下**每个技能**都有此需求，再沿映射汇总 |

同一门课既有课程级、又有技能级的同一条件时，两条都保留，汇总时按第 6 节取较强级别。

## 5. 来源与状态

### 5.1 状态流转

```
                 AI 生成                         人工新增
                    │                               │
                    ▼                               ▼
                 待审核 ──通过──▶ 已审核 ◀────────(直接)
                    │                ▲
                    ├──修改后通过──▶ 已调整
                    │
                    └──驳回──▶ 驳回 ──恢复──▶ 待审核（AI 的）/ 已审核（人工的）

  挂载节点在知识体系中被删除 ──▶ 失效（任何状态）；节点恢复 ──▶ 回到失效前状态
```

| 操作 | 允许的起始状态 | 结果 | 说明 |
|---|---|---|---|
| 通过 | 待审核 | 已审核 | — |
| 修改后通过 | 待审核、已审核、已调整 | 已调整 | 改条件或级别；原值写入 origin |
| 修改依据文字 | 任意有效状态 | 状态不变 | 只改 basis 不算调整 |
| 驳回 | 待审核、已审核、已调整 | 驳回 | 必须填理由；**不物理删除**，用于阻止 AI 重新生成同一条 |
| 恢复 | 驳回 | AI 的回到待审核，人工的回到已审核 | — |
| 人工新增 | — | 已审核 | 人工新增即视为审核通过 |
| 删除 | 仅人工新增且有效的 | 物理删除 | 留操作日志；AI 生成的不可删除，只能驳回 |

### 5.2 权限

| 操作 | 角色 |
|---|---|
| 维护条件字典 | 平台数据管理员 |
| 新增 / 修改 / 驳回 / 恢复实训需求 | 平台数据管理员、该专业的知识体系审核专家 |
| 触发 AI 重新生成 | 平台数据管理员 |
| 填报本校实训资源与同时上课人数 | 学校：有「发起能力测评」权限的身份 |
| 录入数量标准 | 平台数据管理员（须填出处与原文摘录） |

## 6. AI 重新生成时的合并规则（核心）

触发：知识体系更新、条件字典更新、推导规则更新，或管理员手动触发。生成范围可以是整个专业，也可以是指定课程或技能。

对 AI 新产出的每一条 `(target, condition)`，按下表处理：

| 库中已有同一 (target, condition) 的记录 | 处理 |
|---|---|
| 无 | 新增，source = auto，状态 = 待审核 |
| auto · 待审核 | 用新结果**覆盖**级别与依据（仍为待审核） |
| auto · 已审核 / 已调整 | **不动** |
| auto · 驳回 | **不动**，不重新出现 |
| manual · 任意状态 | **不动** |
| 课程级记录（人工） | 不影响技能级的生成；两条并存 |

对库中**本次 AI 没有再产出**的记录：

| 已有记录 | 处理 |
|---|---|
| auto · 待审核 | 删除（AI 自己的未审核草稿，以新结果为准） |
| auto · 已审核 / 已调整 / 驳回 | 保留，标记「本次生成未再出现」，供专家复核 |
| manual | 保留 |

**一句话：AI 只改它自己生成、且还没人碰过的记录。**

生成结束后输出一份生成报告：新增 n 条、覆盖 n 条、删除 n 条、跳过（已人工处理）n 条、「未再出现」n 条、字典新增建议 n 条。

## 7. 汇总口径

维护与汇总展示使用**有效记录**（状态为待审核、已审核、已调整）。**进入能力测评的只有已确认记录（已审核、已调整）**，待审核不计入，也不提供开关（2026-10-21 定）。

| 汇总 | 规则 |
|---|---|
| 课程 → 条件 | = 课程级记录 ∪ 课程下全部技能级记录。同一条件出现多次时取较强级别（必需 > 建议） |
| 能力 × 等级 → 条件 | 取映射为「直接支撑 / 部分支撑」、服务等级为 Lx、且不是驳回的「技能 → 能力」映射，汇总这些技能的条件（含其所属课程的课程级条件） |
| 等级累进 | 把能力教到 Lx 所需的条件 = L1 至 Lx 各级条件的并集 |
| 测评范围 | 只计本校**已开设**课程（以及其中未被去勾的技能） |

## 8. 在能力测评中的使用

### 8.1 本校对照

标准 = 本校已开设课程的已确认实训需求；本校 = 登记的「在用」实训资源。差距（缺、工位不足）即建设项。

**录入方式**（测评第 ② 步，2026-10-22 合并为一张表）：列出「标准要求的实训条件」（按本校开设课程的已确认实训需求汇总，必需在前；必需行只列必需该条件的课程），学校在每一行填写本校由哪个实训资源提供——从已有资源中选择或输入新名称（新名称即新建一个实训资源，校外基地类条件建为校外、其余为校内），没有就留空；清单随开设课程的勾选实时变化。不再单独维护实训资源表：资源不再提供任何条件时自动移除；只有该条件存在数量标准时，才在资源旁显示工位数输入。

对测评范围内每项**必需**条件：

| 本校情况 | 结论 |
|---|---|
| 无「在用」资源具备该条件 | 缺 |
| 有，且该条件**有数量标准**，本校工位数合计 < 建议工位数 | 工位不足（显示「本校 x / 建议 y · 依据：标准名称 条款号」） |
| 有，且有数量标准，工位足够 | 具备（可显示「本校 x / 建议 y」） |
| 有，该条件**没有数量标准**，或学校未填工位数 / 同时上课人数 | 具备（不显示任何数量） |
| 条件类别为校外基地 | 只判「具备 / 缺」，另列基地可承接的岗位与面向岗位的对照 |

建议条件只列出，不计入具备率。

### 8.2 报告呈现（「④ 实训条件差距」）

| 位置 | 内容 |
|---|---|
| 指标 | 必需实训条件具备 x / y 项 |
| 明细表 | 条件名称、类别、本校结论（缺、工位不足排在前面）、需要它的课程、影响的岗位能力（能力名 + 等级）、来源（AI / 人工） |
| 建设与提升项 | 每项「缺」生成一条，写「标准要求：《课程》必需该条件；本校没有」；「工位不足」仅在有数量标准时生成，依据中写明标准出处。优先级按影响面定（涉及 ≥ 1 条目标岗位核心能力，或 ≥ 2 门已开设课程必需该条件，为高；否则中）；依据写明服务的课程与能力 |
| 数据口径 | 注明「已确认实训需求 n 条（含人工维护 n 条）」；有数量标准的条件列出标准出处，没有的不出现数量相关文字；已确认需求为 0 时整节显示「本专业暂无已确认的实训需求，本次不作实训条件对比」 |

## 9. 校验与提示

| # | 场景 | 处理 |
|---|---|---|
| V1 | 新增需求时条件已停用 | 不可选；列表中灰显 |
| V2 | 新增与已有有效记录重复的 (target, condition) | 阻止保存，提示「该条件已存在（来源 / 状态）」并可跳转 |
| V3 | 课程级新增的条件，已在该课程部分技能上存在 | 允许保存，提示「已有 n 个技能单独标注了该条件」 |
| V4 | 人工新增未填理由 | 阻止保存 |
| V5 | 驳回未填理由 | 阻止提交 |
| V6 | 挂载节点被删除 | 记录转为失效，不参与汇总；在「失效记录」中可查 |
| V7 | 挂载节点改名 | 按 ID 关联，记录不受影响 |

## 10. 验收用例

| # | 步骤 | 预期 |
|---|---|---|
| T1 | 人工给技能「导游词结构化创作与修辞运用」新增「讲解实训室 · 建议」，理由「需录像点评初稿试讲」 | 保存成功，source = manual，状态 = 已审核；课程《导游词创作与讲解》汇总中出现该条件 |
| T2 | 在 T1 之后触发 AI 重新生成整个专业 | T1 的记录不变；生成报告「跳过（已人工处理）」计数包含它 |
| T3 | 驳回 AI 生成的「旅游英语 · 景点概况与历史背景介绍 → 语言实训室」，理由「普通教室可完成」后，重新生成 | 该条不再出现，状态仍为驳回 |
| T4 | 把 AI 生成的「现场救护 · 伤员搬运技术 → 急救技能训练器材」级别从必需改为建议 | 状态 = 已调整，origin 记录原级别「必需」；重新生成后不被覆盖 |
| T5 | 给课程《模拟导游》新增课程级「导游服务综合实训室 · 必需」 | 课程汇总为必需；该课程支撑的每条能力 × 等级汇总中都出现该条件 |
| T6 | 在字典中停用「虚拟景区与云导览资源」 | 新增需求时不可选；已有引用标「条件已停用」，仍参与汇总 |
| T7 | 删除一个被引用的字典条目 | 被阻止，提示改为停用 |
| T8 | 把字典条目 A 合并到 B，某技能同时引用 A（建议）和 B（必需） | 保留 B（必需），A 那条驳回，理由「合并重复条件」 |
| T9 | 知识体系中删除技能「烧烫伤现场处理」 | 其实训需求转为失效，不出现在课程与能力汇总中 |
| T10 | 某专业实训需求一半待审核、一半已审核 | 测评只用已审核、已调整记录；第 ② 步「生成报告」旁提示「有待确认的数据，本次不计入」（不显示条数） |
