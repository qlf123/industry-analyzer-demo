## 1. 要回答的问题与数据链路

能力测评要回答：**本校一个专业，教出来的学生能不能胜任行业岗位？差在哪？实训资源够不够？**

> 测评规则（2026-10-21 定）：
> 1. **只用已确认的数据**：映射、实训需求须经人工确认（状态为「已审核」「已调整」）才进入测评；待审核、驳回、失效的一律不计入，也不提供「计入待审核」的选项。
> 2. **本校对比标准，差距即建设项**：标准 = 目标岗位的能力要求 + 专业知识体系全部课程 + 已确认映射 + 已确认实训需求；本校 = 职业面向 + 开设的课程 + 登记的实训资源。报告只呈现两者的差距及由差距推导的建设与提升项；标准本身达不到岗位要求的，单列为「标准未覆盖」，不计入本校差距。

> 范围说明（2026-10-21 定）：专业建设评估**不做学时、学分层面的分析**，不采集学时、学分、实践学时、学期、必修 / 选修与集中实践，也不做人才培养方案比例规定（总学时、实践占比等）的对照。

```
行业侧（能力图谱）                         教学侧（知识体系 + 本校方案）
行业 → 子行业 → 岗位 ──要求(L1–L3)──→ 能力项 ←──映射(类型+等级)── 技能规范 ← 任务 ← 课程 ← 专业
                                                                      ↑
                                              本校专业数据：职业面向、开设了哪些专业课程、实训资源
```

报告的每一个结论都必须能沿这条链追溯到具体数据；链路上任何一环缺失，对应结论不出（见第 8 节）。

| 报告维度 | 用到的数据 |
|---|---|
| ① 产业对接 | 能力图谱（岗位→能力+要求等级）、本校专业数据（职业面向） |
| ② 岗位能力差距 | 能力图谱、已确认映射、知识体系（技能→课程）、本校专业数据（开设课程） |
| ③ 课程差距 | 知识体系全部课程 vs 本校开设课程、已确认映射 |
| ④ 实训条件差距 | 已确认实训需求（第 5A 节）、本校登记的实训资源 |
| 建设与提升清单 | 由 ②③④ 的差距推导 |
| 标准未覆盖项 | 标准本身达不到岗位要求的能力（不计入本校差距） |
| 岗课赛证、师资（后续） | 本校证书与竞赛、师资统计 |

### 4.2 现状

| 数据 | 条数 | 状态 | 问题 |
|---|---|---|---|
| 映射调整清单（人工审核） | 270（13 个专业，导游 23） | 已审核 | 审核前 AI 等级 257/270 为 L1 |
| 映射补充数据（AI） | 184（13 个专业，导游 14） | 待审核 | 等级全部 L1 或空——与上一行同一偏差 |
| **合计** | 454 | | 导游专业 134 个技能只有 32 个有映射；「导游」岗位 15 条能力仅 6 条有支撑 |

**结论**：现有映射有两个系统性问题——①等级判定默认 L1；②从能力出发挑技能、未按专业把每个技能过一遍，覆盖严重不足。两者都会让测评把绝大部分能力误判为「无支撑 / 低于要求」。

### 4.3 处理

1. 映射系统的 AI 生成步骤改用映射 skill 的规则（逐级比对 L1–L3 描述、依据写明对应哪一级；以专业为单位覆盖全部技能）。
2. 导游专业已按该规则产出草稿 **148 条**：已审核 23 条（以审核结果为准）+ AI 补充 14 条重判 + 新增 111 条，134 个技能全部给出结论（112 个有计入类映射，3 个仅前置支撑，19 个判定无对应能力并写明原因）。**待人工审核**，文件见开头。
3. 其余 12 个专业：待各专业知识体系导出后按同一规则生成。

| 实体 | 字段 | 来源 | 现状 |

| 实训条件字典 | id、名称、类别（场地 / 场景 / 设备耗材 / 软件 / 校外基地）、功能要点、来源 | 平台维护 | 草稿 21 项（沿用原中职字典 10 项，去掉无法核实的数量规定；新增 11 项） |
| 实训需求（挂技能或课程） | 挂载类型（技能 / 课程）、挂载节点 id、条件 id、级别（必需 / 建议）、依据、来源（auto / manual）、审核状态 | 平台推导 + 人工维护与审核；课程级只由人工创建 | 导游草稿 107 条（必需 40、建议 67），134 个技能中 93 个有需求、41 个普通教室即可 |
| 汇总 | 课程 → 条件（任一技能必需即必需）；能力 × 等级 → 条件（沿映射汇总，等级累进） | 计算 | 草稿中已给出课程汇总与 49 个能力 × 等级组合 |
| 本校实训资源 | 实训室 / 基地名称、类型、具备的条件 id、工位数、服务课程；校外基地还需合作企业、可承接岗位与人数 | 学校填报 | **无** |
| 数量标准 | 条件、规定方式（每工位人数 / 最少数量）、数值、出处、原文摘录；学校另填同时上课人数 | 标准原文（平台录入）+ 学校填报 | **无**；不设默认值。无标准的条件不显示任何数量，也不判工位不足 |
| 标准规格（可选） | 面积、配置标准、必配清单 | 专业教学标准 / 实训教学条件建设标准原文 | **无**；有原文才做标准对照 |

## 7. 计算口径

与映射 skill 的「测评计算口径」一致：

| 指标 | 口径 |
|---|---|
| 计入的映射 | 类型为直接支撑 / 部分支撑，且状态为「已审核」或「已调整」；待审核、驳回不计入 |
| 标准可达等级 | 知识体系**全部课程**中计入映射服务等级的最大值 |
| 本校达到等级 | 本校**已开设课程**中计入映射服务等级的最大值 |
| 能力结论 | 标准可达 < 岗位要求 →「标准未覆盖」（不计入本校差距与达标率）；否则本校达到 ≥ 要求 →「达到要求」，0 < 本校达到 < 要求 →「低于要求」，本校无支撑 →「本校未覆盖」。达到或低于要求且无直接支撑时追加「仅部分支撑」（说明，不算差距） |
| 岗位达标率 | 达到要求的能力数 ÷ 标准可达到要求的能力数；分母为 0 时显示「—」 |
| 岗位能力雷达图 | 每个面向岗位一张：轴 = 该岗位要求的能力（★ 核心），刻度 L0–L3；三层 = 岗位要求（虚线）、标准可达（灰）、本校达到（主色）；本校差距的能力标红，标准未覆盖的置灰；岗位要求能力少于 3 条时不画 |
| 课程差距 | 知识体系中有、本校未开设的课程；列出开设后可补的目标岗位能力及可达等级；不影响目标岗位能力的未开设课程只列名称 |
| 建设与提升项 | 能力差距：一条能力一项，写「标准要求 Lx（岗位），本校当前 Ly / 未覆盖，开设《课程》可达到」，本校未覆盖或核心能力为高优先级，否则中；实训条件差距见第 5A 节 / 实训规则 §8 |
| 待确认数据 | 不计入；测评第 ② 步「生成报告」旁提示「有待确认的数据，本次不计入」（不显示条数；新建测评为两步：选专业 → 核对本校数据并生成），确认后重新测评即可纳入 |
| 不再呈现 | 可拓展的职业面向、不支撑目标岗位能力的课程、只有一门课支撑的能力（均非「本校对比标准」的差距） |

**待确认**：「部分支撑」到 L3 是否算达到 L3（当前口径：算，同时标「仅部分支撑」）。
