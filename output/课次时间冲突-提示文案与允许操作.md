# 课次时间冲突：提示文案与允许操作汇总

> 覆盖 4 个环节：教师端新建/编辑课次、管理端排课、教师端待审核课次、管理端课次审核。
> 冲突判定统一为「同一天 + 同班级（多班合班时任一班占用即冲突）或同授课老师 + 时间段重叠」；已停用课次时间已释放，不参与判定。

## 一、教师端 · 新建 / 编辑课次（本次调整）

输入时间即实时检测，改时间自动恢复。冲突对象描述格式：`〈班级〉 这时有《课程》` 或 `〈老师〉 这时在上《课程》（〈班级〉）`，后接 `（MM-DD HH:MM–HH:MM）`。

| # | 冲突对象 | 提示文案 | 允许操作 |
|---|---|---|---|
| 1 | 已发布课次（任何来源） | 与已发布的课次时间冲突：〈对象〉。已发布课次无法撤回，不能提交教务审核，请调整上课时间。 | 「创建 / 保存」置灰；只能改时间 |
| 2 | 其他老师的课次（自建 / 补训 / 辅导，未发布） | 与其他老师的课次时间冲突：〈对象〉。教务没有权限调整老师自建的课次，不能提交教务审核，请调整上课时间。 | 「创建 / 保存」置灰；只能改时间 |
| 3 | 教务排课 · 未发布 | 与教务排课的课次时间冲突：〈对象〉。请调整上课时间或提交教务审核。 | 「创建 / 保存」置灰；可「提交教务审核」或改时间 |
| 4 | 自己的课次（自建 / 补训，未发布） | 时间冲突：〈对象〉。课表里两个课次会重叠显示。 | 不拦截；「仍要创建 / 保存」确认后落库 |

> 核心规则：**只有「与教务排课且未发布的课次」冲突，才能提交教务审核**；与已发布课次冲突（无法撤回）、与其他老师自建课次冲突（教务无权限调整）都不能提交审核，只能改时间。

## 二、管理端 · 排课（排一次 / 批量 / 编辑）

| 场景 | 提示文案 | 允许操作 |
|---|---|---|
| 排一次课冲突 | 这个时间有冲突，这次课还没排：调整日期或节次后再点「确定」<br>〈日期〉〈节次〉 · 〈原因〉 | 弹框不关、不落库；改时间再提交 |
| 批量排课部分冲突 | 部分时间冲突，这次课还没排：调整日期或节次后再点「确定」<br>按钮「跳过冲突，只排不冲突的 N 次」 | 改时间；或跳过冲突、只排不冲突的 |
| 编辑排课时间冲突 | 同「排一次课」 | 不改，留在弹框 |

冲突原因：`已排了这门课` ／ `班级已有《〈课程〉》` ／ `〈老师〉已有课`

导入校验：时间冲突的排课不导入并写明原因。

## 三、教师端 · 待教务审核课次

| 位置 | 文案 | 允许操作 |
|---|---|---|
| 时间线分组 | 待教务审核（N）｜与教务排课时间冲突的课次，等教务在管理端处理；通过后可正常备课发布，不需要可撤回申请 | 只「撤回」 |
| 行内状态 | 待教务审核 · 与教务排课时间冲突 | 撤回 |
| 撤回确认 | 撤回「〈课次名〉」的审核申请吗？待审核课次会一起删除。 | 撤回＝删除课次＋审核单标「已撤回」 |

> 待审核课次不计入教学进度、待发布、已过期、下次课等任何统计；审核通过 / 替换通过转未发布后自然计入。

## 四、管理端 · 课次审核（教务处理动作）

| 动作 | 提示 / 校验文案 | 结果 |
|---|---|---|
| 通过（未调时间） | 请先展开「调整课次时间」，调整到无冲突时段后再通过；或「请先调整到无冲突的时间再通过；要保留老师课次的时间、顶替原排课，请用『替换排课』」 | 拦截 |
| 通过（调整后仍冲突） | 调整后仍与《〈课程〉》（MM-DD）冲突，请换一个时段 | 拦截 |
| 通过（调整到无冲突） | — | 课次转「未发布」，记「教务已调整时间」 |
| 替换排课（原排课已发布） | 原排课课次已发布，不能替换；请调整老师课次时间后用「通过」处理 | 拦截 |
| 替换排课（正常） | 已通过，老师课次已替换原排课《〈课程〉》，原课次已停用 | 老师课次转未发布；原排课停用（时间释放） |
| 驳回 | 驳回这条审核申请？教师端的待审核课次会一起删除，老师需要调整时间后重新创建。 | 审核单「已驳回」；老师课次退回删除 |

> 「直接通过（允许时间重叠）」已去掉——通过必须调整到无冲突时间。
