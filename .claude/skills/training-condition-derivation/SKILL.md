# 实训条件需求推导规则

知识体系没有实训条件字段，但技能的达成结果、操作步骤、标准、案例里写着「学生要在什么环境下、用什么做什么」。本规则把这些信息整理成可汇总、可核对的实训条件需求。

**定位**：推导结果叫「按课程内容推导的实训需求」，**不是**国家标准规定的实训条件。只有拿到专业教学标准或实训教学条件建设标准原文后，才能判「符合 / 不符合标准」。规格与数量（工位数、台套数、面积）不从知识体系推导。

## 推导规则

### 输入
- 实训条件字典（受控词表）：编号、名称、类别（场地 / 场景 / 设备耗材 / 软件 / 校外基地）、功能要点。只能从字典里选；字典里没有的，提出新增建议，不自造名称。
- 技能规范：完整路径（专业 › 课程 › 任务 › 技能）、可观察能力要求、达成结果、操作步骤、标准、案例。

### 判定
对每个技能逐一判断，输出 0–3 项条件：

| 级别 | 标准 |
|---|---|
| **必需** | 达成结果或操作步骤里的动作，离开该条件无法完成或无法考核（如「完成 30 次胸外按压」需要心肺复苏模拟人；「在后台配置库存日历」需要店铺运营软件） |
| **建议** | 有该条件教学效果明显更好，但普通教室或纸面也能完成（如英语口语对话、行程线路图绘制） |
| 不输出 | 纯理论、概念辨析、方案撰写等普通多媒体教室即可完成的技能 |

- 以达成结果和操作步骤为准，不因课程名或技能名里有「模拟」「实训」就判必需。
- 同一技能需要多项条件时分别输出；能由一项综合实训室覆盖的，不拆成多个设备。
- 校外基地只在「必须到真实场景」时判必需（如实地资源调查、跟团带团）；能在校内模拟的判建议。

### 依据
每条结果写明：技能侧原文（引用达成结果或步骤）＋ 为什么需要该条件。

### 汇总
- **课程**：开设该课程需要的条件 = 课程下全部技能条件的并集；任一技能必需即为必需。
- **能力 × 等级**：沿「能力 ↔ 技能」映射（只计直接支撑 / 部分支撑），把支撑该能力该等级的技能的条件汇总起来，得到「把这条能力教到 Lx 需要哪些条件」。
- 等级累进：教到 Lx 需要的条件 = L1 至 Lx 各级条件的并集（汇总表按单级列出，使用时累加）。
- **数量**：推导中不给出任何数量。只有标准原文规定了数量（每工位人数或最少台套数，带出处）时，测评才显示建议工位 / 台套数；没有标准的条件不显示任何数量，不用默认值或估算值补位。

### 人工维护与重新生成（完整规则见 docs/能力测评/实训条件-数据与维护规则.md）
- 需求可挂在**技能**或**课程**上；课程级只由人工创建，视为课程下每个技能都需要。
- 来源 auto / manual；状态：待审核 / 已审核 / 已调整 / 驳回 / 失效。人工新增直接为已审核；AI 生成的只能驳回、不能删除。
- 能力测评只计入已确认（已审核、已调整）的实训需求；草稿须人工确认后才进入测评。
- 重新生成时**只改 AI 生成且仍为待审核的记录**；已审核、已调整、驳回的 AI 记录和全部人工记录都不动，驳回的不再出现。
- 只引用字典中「启用」的条件；字典缺项时输出新增建议，不自造条目。

### 本校对照（测评报告使用）
- 本校实训室 / 基地登记它具备字典中的哪些条件，工位数选填。
- 某条件：本校无 → 缺；有，且有数量标准、本校工位数 < 建议数 → 工位不足（附标准出处）；其余 → 具备，不显示数量。
- 只对「已开设课程的必需条件」出结论；建议条件单列，不计入「具备率」。

## 在 Claude Code 里使用
1. 读入字典与某专业知识体系，按上方规则逐个技能判定，产出草稿（状态：待审核）。
2. 输出给审核用的表格：技能需求明细、课程汇总、能力 × 等级汇总、字典。
3. 审核后的结论覆盖草稿；字典新增项需同步到字典。
