# 能力项 ↔ 技能规范 映射规则

两张图谱唯一的直接连接是「能力 —— 技能」（见项目根目录《双图谱结构说明.md》）。一条映射回答两个问题：
1. 这个技能**能不能**支撑这条能力（映射类型）；
2. 学完这个技能，能把这条能力支撑到**哪一级**（服务等级 L1–L3）。

规则依据：2026-10 人工审核的 270 条映射（`raw-data/映射调整清单_旅游行业_2026-10).xlsx`）中审核人员的调整理由。审核前 AI 给出的等级 257/270 都是 L1，审核后以 L2 为主——**最常见的错误就是不比对等级描述、默认给 L1**，本规则首先要防这一点。

## 映射规则

### 输入
- **能力项**：名称、定义，以及 L1 / L2 / L3 三级「行为描述 + 观测点」。
- **技能规范**：完整路径（专业 › 课程 › 任务 › 技能）、「可观察能力要求」「达成结果」，以及其下的操作步骤。
- 判断以技能的**达成结果**为准（学完能做到什么），可观察能力要求和操作步骤作补充；不以技能名称字面相似为依据。

### 第一步：判定映射类型

| 类型 | 判定标准 | 服务等级 |
|---|---|---|
| **直接支撑** | 技能的达成结果，完整覆盖能力某一级行为描述的主要动作（该级描述里的关键动词和对象都能在技能中找到） | 必填 |
| **部分支撑** | 技能只覆盖能力某一级行为描述中的一部分动作，或只覆盖其中一个场景 / 对象 | 必填 |
| **前置支撑** | 技能是该能力的前置知识或基础操作，本身不产生能力描述中的行为，但缺了它无法形成该能力（如「旅游法规条款理解」之于「合规签署」） | 必填（标其能支撑到的前置等级，通常 L1） |
| **相关但不构成覆盖** | 同一领域或话题相近，但技能的行为与能力的行为不同（如「食宿安排与监督」之于「信息咨询」） | 留空 |

- 名称相似不等于支撑；领域相同但动作不同，判「相关但不构成覆盖」。
- 一个技能可以映射多条能力；一条能力可以由多个技能共同支撑。
- 「相关但不构成覆盖」只在确有误判风险时记录（帮助审核排除），不必穷举。

### 第二步：判定服务等级（逐级比对，禁止默认 L1）

从 L3 往下逐级比对，取技能达成结果**真正达到**的最高一级：

| 等级 | 能力描述的典型特征 | 技能侧对应信号 |
|---|---|---|
| L1 | 「在指导下」「按模板 / 清单 / 标准话术」「协助」「记录、核对、上报」 | 达成结果是按规定完成、复述、填写、识别、按清单检查 |
| L2 | 「独立」完成；能根据客群 / 现场 / 天气等情况调整；能处理异常、组合方案、解答个性化问题 | 达成结果包含独立完成整件事、针对情境调整、处理变化或异常 |
| L3 | 「设计 / 制定 / 编制」方案、预案、标准、体系；「评审他人」「指导他人」；统筹多团队、复杂或高风险情形 | 达成结果产出方案 / 预案 / 标准，或包含评审、指导、统筹 |

- 「部分支撑」的等级 = 所覆盖的那部分动作所在的级别（审核示例：「互动答疑对应 L2『解答个性化疑问』的一部分」→ 部分支撑 L2）。
- 达成结果只到「能说明、能识别」而能力 L1 要求实际操作的，不构成支撑；只是知识储备的，考虑「前置支撑」。
- 不得因为是课程中的入门技能就一律判 L1，也不得因为技能名含「设计」就判 L3，必须对照达成结果。

### 第三步：写判断依据（basis）
依据必须同时写出：
1. 技能侧：引用达成结果或关键操作步骤原文（摘要即可）；
2. 能力侧：**写明对应哪一级的哪句描述**，格式「对应 L2『……』」；
3. 部分支撑时，写明缺了能力描述中的哪部分。

示例：
- 直接支撑 L2 —— 「分段讲解与现场互动，对应 L2『根据游客年龄结构和现场反应即时调整讲解深度与互动方式』」
- 部分支撑 L2 —— 「服务补救方案制定与执行跟进，对应 L2『协调处置并回复』；不含知识库优化（L3）」
- 相关但不构成覆盖 —— 「购物引导不是信息咨询，行为对象不同」

### 覆盖要求（按专业生成时）
- 以**专业**为单位：该专业知识体系中的**每一个技能规范**都要与能力图谱的全部能力逐一比对，不能只从能力出发挑几个最像的技能。
- 每个技能输出 0–3 条计入类映射（直接 / 部分 / 前置）；确实不支撑任何能力的技能，输出空结果并说明原因（如纯知识类、与行业岗位无关）。
- 置信度 confidence：依据充分、动作一一对应给 0.85 以上；需人工确认等级的给 0.6–0.8。

### 测评计算口径（能力测评报告使用）
- 测评是「本校对比标准」：标准 = 目标岗位能力要求 + 专业知识体系全部课程 + 已确认映射；本校 = 开设的课程。差距即建设或提升项。
- 计入「能力被支撑」的只有：直接支撑、部分支撑，且审核状态为「已审核」或「已调整」（人工确认过）。待审核、驳回一律不计入。
- 前置支撑、相关但不构成覆盖：在报告中展示，不计入覆盖。
- 标准可达等级 = 知识体系全部课程中计入映射的最高服务等级；本校达到等级 = 已开设课程中的最高服务等级。
- 标准可达 < 岗位要求 →「标准未覆盖」，单列，不计入本校差距与达标率；否则按本校达到等级判「达到要求 / 低于要求 / 本校未覆盖」。
- 只有部分支撑、没有直接支撑的能力，标「仅部分支撑」（说明，不算差距）。

## 输出字段（与映射系统一致）

`id`、`system_id`、`system_name`（专业知识体系）、`knowledge_node_name`、`knowledge_node_type`（技能规范）、`graph_id`、`graph_name`、`ability_node_name`、`mapping_type`、`service_level`、`confidence`、`basis`、`source`（auto / manual）、`status`（待审核 / 已审核 / 已调整 / 驳回）、`creator_name`、`updater_name`、`created_at`、`updated_at`。

建议补充：`knowledge_node_id` 或 `knowledge_node_path`、`ability_node_id`——只有名称时，节点一改名映射就断。

## 在 Claude Code 里使用
1. 读入能力图谱（含 L1–L3 描述）与某专业知识体系（含技能的可观察能力要求、达成结果、操作步骤）。
2. 按上方规则逐个技能判定，产出草稿，`source` 记 auto、`status` 记 待审核。
3. 已有人工审核结果的映射，以审核结果为准，不覆盖。
4. 产出给人工审核用的表格时，按「专业 › 课程 › 技能」排序，列出类型、等级、依据，方便逐条确认。
