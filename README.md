# 行业分析 · 能力全景（功能模块 1 · 可点高保真原型）

AIGC 智慧课堂教学平台 · 管理端的「行业分析」模块。校领导 / 专业负责人输入行业，
查看该行业的四层能力全景，并可叠加本校情况做覆盖诊断。

**在线预览**：`panorama.html`（单文件，双击即可在浏览器打开，无外部依赖）

---

## 一、这个模块的边界

平台分两块，职责不同：

| | 图谱平台 | 本模块（行业分析） |
|---|---|---|
| 干什么 | 造图并确认 | 用图 |
| 谁在用 | 业务方 / 行业专家 | 校领导 / 专业负责人 |
| 产出 | 行业边界、子行业划分、岗位清单、能力项与证据 | 全景视图、能力测评、缺口处置建议 |

**核心原则：本模块只呈现已确认的数据，不出现需要用户拍板的内容。**
所有不确定的判断都在图谱平台建图时一次性定好并随图谱入库。

原型内保留了图谱平台的构建流水线演示（输入未建图的行业 → 点「分析」→ 抽屉里的按钮），
但它被明确标注为「图谱平台 · 构建流水线」，不参与行业分析本身。

## 二、页面结构

```
行业输入框（分析按钮）
├─ 行业全景
│   ├─ 能力图谱      环形（旭日）/ 树形（四列连线）/ 卡片 三种形态
│   ├─ 能力矩阵      岗位 × 能力项，格子色 = 要求等级
│   └─ 趋势与新兴    产业趋势（背景判断，无来源）+ 新兴能力项（有来源）
├─ 能力测评
│   ① 数据来源  本校能力达成填报 / 课程体系勾选 / 双图谱自动诊断
│   ② 测评范围  岗位多选，决定后续全部计算的范围
│   ③ 采集/计算 随来源变化
│   └─ 诊断报告  能力结构对比 → 全景定位 → 岗位达标 → 诊断结论 → 缺口处置建议
└─ 页脚说明     数据时效 / 行业边界 / 排除项 / 纳入范围 / 数据可信度
```

## 三、三种数据来源

按学校数据沉淀程度从少到多：

1. **本校能力达成填报** —— 本校没有任何数据沉淀。由专业负责人逐条填报「教到什么程度」。
   结论反映填报人判断，不可追溯到知识点。
2. **课程体系勾选** —— 本校没有自己的知识图谱，但平台预置了按专业教学标准建的课程体系
   （课程 → 知识点 / 技能规范）。勾出本校已有的内容，达成等级沿映射边逐条节点推出。
   支持两级勾选：勾课程 = 勾中其下全部节点；展开后也可只勾其中几条。
3. **双图谱自动诊断** —— 本校已接入自己的知识图谱。结论由映射边自动推导，
   可追溯到具体课程、任务与知识点。

三种来源产出同结构的报告，都可叠加回「行业全景」，都进版本历史与导出。

## 四、缺口处置建议

报告末尾按承接形态给出建议，**每一段都有出处，不生成没有依据的内容**：

| 内容 | 取自 |
|---|---|
| 承接形态（新增模块 / 课内加深 / 实训顶岗） | 可写明的判定规则 |
| 要教到什么程度、达标考核 | 能力项的三级行为化描述 |
| 教学蓝本 | 该能力的来源证据（带 URL 与原文片段） |
| 补齐顺序 | 能力项之间的 prerequisites |
| 补哪门课、补哪几个知识点 | 课程体系的映射边（仅「课程体系勾选」模式） |
| 实训条件 | 课程的实训要求 × 本校实训室清单比对 |

学时、开课学期、课程名不生成——图谱里没有依据，那些在《课程计划管理》里由教务决定。

## 六、怎么改

```bash
python3 build_panorama.py      # 改完数据或模板后重新构建
```

- **改数据** → 编辑 `data_*.py` / `panorama_ext.py`，重新构建
- **改界面** → 编辑 `panorama_template.html`，重新构建
- **直接改 `panorama.html` 会在下次构建时被覆盖**

数据结构说明见各 `data_*.py` 文件头部的注释。

## 七、已知的口径问题

原型中有几处展示口径尚未在图谱平台定成规则，正式化前需要确认：

1. **核心能力** —— 已按 V2 方案《归并规则 6》（被 2 个以上岗位要求 **且** 有国家级来源）计算。
   但该口径会让「服务礼仪与职业形象呈现」这类被 7 个岗位要求、却无国标背书的能力掉出核心集，
   是否改为「或」值得讨论。
2. **通用 / 共性 / 岗位专项**（三档上浮）—— 不在 V2 方案里，是原型的展示口径。
   「共性」一档因判定门槛依赖子行业岗位数、会随建图范围漂移，目前已隐藏（算法保留）。
3. **产业趋势** —— 由建图模型直接输出，无来源证据、未经原文校验，页面已如实标注。
   若要让这一节立得住，建议 N3 抽取时记录 `fromTrend`，使趋势可追溯到它产出的新兴能力。
