01一页纸结论

建议结论：有条件推进。本项目的教育场景和政策方向成立，但不建议直接建设“全功能智慧教学平台”。首期应验证一个窄闭环：标准结构化 → 岗课赛证映射 → 任务/教案生成 → 教师审核 → 课堂使用 → 形成能力证据。

项目判断产品化结论
解决什么问题把分散的岗位、课程、证书、赛项标准转成可维护的能力模型，并辅助教师生成可审核、可复用的任务和教学文件。
不解决什么问题不替代国家职业教育智慧教育平台、学校教务系统、通用 LMS，也不承诺由 AI 自动制定教学标准或自动判定学生能力。
首个付费价值帮助一个专业在较短周期内完成标准梳理、课程任务重构和教师备课提效，并沉淀为学校可拥有的专业数字资产。
主要商业风险每所学校都需要大量定制，平台可能变成一次性项目；教师和企业导师的持续参与不足，导致图谱建成后无人维护。
推进闸门只有在首期证明教师持续使用、交付成本可控、学校愿意扩展第二个专业后，才进入赛训、学生画像、视频和硬件接入建设。

02产品定位与边界

2.1 产品定位

定位：职业院校的“专业标准治理与能力证据工作台”。它位于国家资源平台、学校教务系统和教师日常教学之间，负责把专业标准变成可执行的教学任务和可追溯的能力证据。
标准治理岗位说明书、证书大纲、赛项规程和行业规范结构化入库，支持版本、来源和变更追踪。
教学生产围绕能力点组装任务，生成教案、工单和评价量规，教师在线修改并审核发布。
证据闭环将实训、测评、竞赛和考证结果关联到能力点，为补训和课程改进提供依据。

2.2 产品边界

属于本产品不属于本产品
专业标准、能力图谱、任务库、教学文件生成、审核流、资源标签、能力证据和影响分析。通用课程资源大商城、全校教务管理、通用即时通讯、完全自动生成的实操视频、无证据支撑的 AI 能力评级。
与国家平台、教务系统、校园统一身份认证进行接口协同。重新建设国家级资源平台或要求学校替换现有校园信息化系统。
定位调整原因：国家职业教育智慧教育平台已经提供专业与课程、教材资源、虚拟仿真实训和教师能力提升等服务，因此本产品应做“专业工作流和数据治理层”，而不是再做一个泛化资源平台。参考：国家职业教育智慧教育平台简介。

03客户、角色与购买逻辑

3.1 首批目标客户

客户条件为什么适合首期筛选问题
有专业建设、实训基地或数字化项目预算具备采购窗口和成果验收需求今年是否有确定预算和项目负责人？
有成熟校企合作关系企业标准和导师参与是图谱质量的前提企业导师能否每两周投入 1–2 小时？
有稳定证书或赛项便于建立可验证的四元映射标准是否公开、稳定、可获得？
技能可观察、可评价实训结果和能力证据更容易量化是否有清晰的操作步骤和评分量规？

建议首期专业：烹饪、机电、汽修、护理、物流等技能特征强且已有企业合作的专业。不要用纯理论专业作为第一验证场景。

3.2 角色分工

角色购买/使用诉求必须交付的价值
校领导 / 项目负责人项目能验收、能形成示范成果成果看板、项目报告、可复制扩展方案
教务处专业建设和教学质量有依据标准版本、课程覆盖、任务和证据报表
专业带头人能维护专业标准，减少重复建设图谱编辑、影响分析、专业资产导出
教师少写重复文件，任务能直接用于课堂任务组装、教案初稿、审核和资源复用
企业导师岗位标准进入课堂，审核成本可控移动/网页轻量审核、标准反馈记录

04核心场景与产品闭环

4.1 首期只做三个场景

场景 A｜专业标准梳理
  1. 导入岗位说明书、证书大纲、赛项规程。
  2. 拆分知识点、能力点、评价指标和安全要求。
  3. 建立岗位—能力—课程—证书/赛项映射。
  4. 专家审核后发布专业标准版本。
场景 B｜教师备课生产
  1. 教师选择 2–4 个能力点。
  2. 系统组装任务目标、步骤、工具和评价量规。
  3. 生成教案或工单初稿，并标注依据来源。
  4. 教师修改、提交审核、定稿入库。
场景 C｜证据回流
  1. 录入课堂实训、理论测验或实操考核结果。
  2. 证据关联到能力点，并保留来源、时间和评分人。
  3. 教师查看共性薄弱点，调整任务和资源。
  4. 学生查看证据和补训任务，不把模型结果当作最终成绩。

4.2 一条可验收的闭环

  1. 标准入库：所有能力点必须有来源和版本。
  2. 能力建模：每个能力点必须有评价指标，能够被任务或考核观察。
  3. 任务组装：能力点自动关联支撑知识、工具、安全要求和评价量规。
  4. 教师审核：AI 只能生成初稿，未经审核不得下发学生。
  5. 课堂使用：任务和工单真正用于至少一个试点班级。
  6. 证据回流：记录结果、评价人和时间，形成可追溯证据。
  7. 课程改进：根据共性薄弱点修改任务或资源，形成版本记录。

05MVP 产品范围

5.1 P0：90 天必须完成

模块功能90 天交付边界
标准与图谱标准源管理、能力点/知识点、关系编辑、来源、版本、变更记录、Excel 导入导出一个专业 ≥150 个能力点；专家可自行增删改和发版
映射与校验岗位—能力—课程—证书/赛项映射，缺失关系和重复关系提示至少完成一个证书或赛项的映射
任务工作台能力点选取、任务组装、工具/步骤/安全/量规字段、Word/PDF 导出≥30 个可课堂使用任务
AI 生成基于图谱上下文生成教案、工单和学习目标，引用来源，实体校验只支持 2–3 种固定模板；禁止任意长文生成
审核与资源教师修改、批注、提交、驳回、定稿、资源标签和版本所有学生可见内容必须经过审核
证据记录实训/测验/考核结果录入，关联能力点，展示证据明细先支持人工录入和模板导入，不做硬件接入

5.2 P1：验证通过后建设

学生补训推荐、赛训管理、证书题库、学生能力画像、学情看板、SSO 对接、移动适配、校本资源跨专业复用。

5.3 P2：暂不承诺

AI 视频生成、数字人、智能实训硬件、跨校图谱市场、自动判定能力等级、复杂开放 API 生态。除非已有明确客户和数据条件，否则这些内容会显著增加成本而不能证明首期价值。

06数据与 AI 设计

6.1 数据对象

对象最小字段质量要求
标准源来源名称、版本、发布日期、原文位置、适用范围无来源不得发布
能力点名称、描述、所属岗位、评价指标、安全要求、来源必须可观察、可评价、可关联任务
任务目标、步骤、工具、风险、评价量规、适用课程至少被一名教师课堂试用
证据学生、能力点、来源、得分、时间、评分人、备注支持追溯、复核和导出

6.2 AI 使用原则

可引用生成内容必须带标准来源和图谱实体引用，不能凭空生成关键参数。
可审核教师审核是发布闸门；涉及安全操作、法规和设备参数时增加企业导师审核。
可撤回标准版本变更后，系统列出受影响的任务和资源，并支持下架或复核。
能力值的定位：首期只展示“基于当前证据的掌握估计”，不作为学生处分、毕业或证书资格的唯一依据。权重、衰减周期和阈值必须通过试点数据校准，并允许教师复核。

6.3 合规与数据边界

  • 学生数据按最小必要原则采集，明确用途、保存期限和导出/删除机制。
  • 学校拥有图谱、任务、资源和证据数据；合同中写明全量导出格式和接口。
  • 外部大模型 API 默认不接收学生个人信息和未脱敏企业资料。
  • 视频、企业标准、数字人声音和图片必须明确版权及授权范围。
  • “私有化部署”不等同于自动满足等保，安全测评、整改和持续运维要单独列明责任。

07商业模式与交付

7.1 产品组合

产品包内容建议计价方式
基础平台包标准源、图谱、映射、任务、审核、资源、证据记录按学校/部署环境收取平台费
专业建设包岗位调研、标准拆分、图谱初始化、任务库建设、专家评审按专业和能力点数量计价
教学提效包教案/工单模板、AI 生成、质量评测、教师培训按专业或教师规模计价
年度服务包标准更新、图谱迭代、模型升级、故障响应、培训年度订阅或服务费
扩展包赛训、证书题库、学生端、SSO、硬件接口按模块和接口复杂度报价

7.2 交付成本控制

  1. 把“平台能力”和“专业内容”拆开报价，避免把定制服务隐藏在软件价格中。
  2. 建立专业模板和标注规范，第二个相近专业的交付内容至少复用 40%。
  3. 首期不承诺每个专业都做同一套图谱；新增专业按工作量单独评估。
  4. 合同明确甲方人力：专业带头人、骨干教师和企业导师必须投入指定时间。
  5. 平台、数据、模型和接口分别验收，避免“功能上线但内容不可用”。

7.3 商业化闸门

闸门必须证明的事实未通过时的动作
G1 场景闸门教师每周真实使用，生成物进入课堂缩减功能，重新做教师工作流
G2 价值闸门备课/教案生产时间下降，任务复用率上升暂停扩展学生端和视频功能
G3 交付闸门第二个相近专业交付成本明显下降把业务定位为咨询项目，不扩大软件投入
G4 续购闸门学校愿意购买第二专业或年度服务调整定价、交付边界和决策人策略

08试点路线与验收

8.1 90 天试点计划

周期工作验收产物
第 1–2 周确定专业、课程、证书/赛项、班级、教师和企业导师；完成标准源盘点试点章程、角色责任书、标准源清单
第 3–5 周能力点拆分、评价指标设计、四元映射、专家评审能力图谱 V1.0、映射报告、质量问题清单
第 6–8 周任务组装、模板配置、AI 初稿、教师审核流、资源标签30 个任务、3 门课程模板、审核流程
第 9–11 周在一个班级真实使用，采集教师时间、修改量、任务完成和证据记录试运行数据、教师反馈、问题清单
第 12 周复盘价值、交付成本和扩展意愿，决定是否进入 P1试点评估报告、二期决策单

8.2 首期验收指标

类别指标建议目标
数据质量能力点有来源、有评价指标、有任务关联的比例≥90%
教师效率教案/工单从初稿到定稿的有效生产时间较基线下降 ≥30%
使用行为试点教师每月至少完成一次有效任务生产≥70%
课堂落地生成任务在试点班级实际使用≥20 个
复用价值任务被不同班级或教师复用≥30%
证据质量证据含来源、时间和评分人，可追溯≥95%
交付能力第二个相近课程的模板复用率≥40%
不建议把“证书通过率提升 10 个百分点”作为 90 天首期硬验收指标。它受学生基础、考试难度、教师投入和样本量影响，适合在至少一届完整教学周期后作为效果指标，并与历史同期或对照班比较。

09风险与前置条件

风险表现控制措施
教师不愿维护图谱成为一次性项目，平台上线后使用率下降把图谱维护纳入专业建设职责；首期只做高频能力点；提供批量导入和复用。
企业导师缺席岗位标准和安全要求无法确认签署参与协议，明确审核范围、频次和费用；企业导师入口保持轻量。
AI 内容不可靠教案或实操步骤出现错误来源约束、实体校验、敏感项人工审核、未审核不可发布。
项目过度定制每个学校都重新开发，毛利下降明确产品边界；定制项单独报价；建立模板和复用率指标。
现有系统重复建设学校已有 LMS、资源库和教务平台以工作台和数据治理层定位，先做接口和数据导出，不替换现有系统。
数据锁定换厂商或迁移困难合同明确数据所有权、全量导出、开放接口、版本历史和迁移协助。

9.1 启动前必须拿到的五个确认

  1. 明确学校的经济买方和项目负责人。
  2. 确认一个专业、一个证书或赛项、三门课程和一个试点班级。
  3. 确认专业带头人、两名骨干教师和至少一名企业导师的投入时间。
  4. 拿到岗位、课程、证书/赛项和安全规范等标准源。
  5. 确认预算、部署环境、数据责任和第二阶段扩展意愿。
