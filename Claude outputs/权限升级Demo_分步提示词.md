# 权限管理升级 Demo · 分步提示词

## 使用方法

1. 先把两份文件放进 Demo 项目：
   - `权限升级Demo_需求说明.md` → `docs/permission-demo-spec.md`
   - `AIGC智慧教学平台_权限管理升级方案_V2.1_开发交付版.docx` → `docs/` 下
2. 按顺序，一次只发一步的提示词给 Code。
3. 每一步结束时，Code 会停下来汇报。你按「这一步做完的标准」检查，没问题再发下一步；有问题就在同一个对话里让它改。
4. 每步之间可以开新对话。每一步的提示词都会先让 Code 读需求说明，所以不依赖上一轮的聊天记录。

| 步骤 | 内容 | 你需要检查什么 |
|---|---|---|
| 1 | 读代码，出实现计划（不写代码） | 计划是否合理 |
| 2 | mock 数据 + 权限模块 + 单元测试 | 测试全部通过 |
| 3 | 公共框架：侧栏、演示身份条、新页面空壳（不改现有页面） | 现有两个页面零改动；从 system.html 进入能切换身份 |
| 4 | 系统配置：组织管理、组织类型、审计日志 | D-12、D-13 |
| 5 | 教务基础数据：专业、班级、年级、学生信息、内容审核（占位） | D-03（审核部分）、D-06、D-08、D-09、D-10 |
| 6 | 账号与角色：账号多角色分配、角色管理 | D-01、D-02、D-03（账号部分）、D-05、D-07、D-11、D-22、D-24 |
| 7 | 教师端 + 学生端：资源三页、教师档案、实习学生、学生本人页 | D-03（作业成绩部分）、D-04、D-14～D-18、D-20、D-21、D-23 |
| 7.5 | 补充：新增组织 / 专业后指定负责人、本节点组织管理员、专业负责人列、组织类型字典权限、部门条线按组织节点限定范围 | D-25～D-30 |
| 8 | 联调、全量验收、演示脚本 | 全部 30 条 D 用例 |

> 验收用例统一用需求说明第 8 节的 **D-xx** 编号。开发交付版第 16 章的 **AC-xx** 是另一套编号，对应关系见需求说明第 8 节最后一列。

## 第 2 步：mock 数据 + 权限模块 + 单元测试

```
这是第 2 步。请先阅读 docs/permission-demo-spec.md 的第 2、5、6、7.10、8 节，以及 docs/permission-demo-plan.md（已确认的实现计划）。

这一步只做数据和逻辑，不做任何页面：

1. mock 数据：按需求说明第 5 节（组织树、专业、年级、班级、学生、基地、资源）和第 6 节（17 个演示身份、每个身份的所属组织和角色分配，以及一个已停用的「停用老师」账号）建好初始数据。数据之间的引用必须一致。
2. 演示数据存储：提供读取、修改、重置演示数据的方法，数据存在浏览器本地，刷新和跨页面都能保留；「重置」恢复成初始数据。
3. 权限模块（纯函数，不碰页面）：
   - 按第 7.10 节实现三步判定：功能权限 → 范围 → 脱敏；
   - 多条角色分配各自生效：只用包含该权限点的那条分配的范围来判断；
   - 范围计算：组织节点及全部下级、年级筛选（只对带年级属性的数据生效）、班主任的指定班级、教师的本人 + 教学范围、企业导师的本基地；
   - 授权约束（第 7.4 节）：不能给自己分配、授出范围不能超出自身、教学范围的授予人规则；
   - 脱敏：按第 7.10 节的脱敏表输出展示值；学生查看本人数据全量；
   - 账号停用：停用账号的全部角色分配失效，任何判定都不通过；
   - 「当前组织」只是视图过滤：权限判定不受它影响，另提供一个按当前组织收窄列表的函数，并能区分「无权限」和「被当前组织过滤」；
   - 每次判定都能返回「判定过程说明」：命中哪条分配、功能是否通过、范围是否通过、用的是哪一档脱敏。后面的「为什么能看到 / 看不到」开关要用它。
   - 权限点、角色模板、脱敏规则写成配置数据，不要写死在函数里。
4. 单元测试：用 Node 自带的测试工具，把第 8 节的 24 条 D 用例在函数层面全部写成测试用例（D-19 测「判定过程说明」的内容是否完整）。页面类用例（例如「看不到按钮」）在函数层面测「这个身份对这个权限点判定为不通过」。

做完的标准：测试全部通过。

完成后停下来，告诉我：新增了哪些文件、怎么运行测试、测试结果，以及实现中你自己补的规则（需求文档没写到的地方）。等我确认后再进入第 3 步。
```
