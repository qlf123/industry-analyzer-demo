## 0. 一句话目标

在 `panorama.html` 新增一个一级页签 **「全景图谱·」**，功能全部做在这个新页签里；现有的「全景图谱」页签（`#l1-kgraph`）**隐藏**。新页签内容：

## 3. 入口：能力树

### 3.1 结构

| 列 | 内容 | 规则 |
|---|---|---|
| 行业 | `kgraph.industry.name` | 1 个节点 |
| 专业 N | `kgraph.majors` | 全部展开，**不能收起**，没有展开 / 收起箭头 |
| 岗位 N | 各专业 `positions` 里 `degree ≠ 不对口` 的岗位 | **去重**：同一岗位只画一个节点，多个专业分别连线过来 |
| 能力项 N | 上面这些岗位要求的全部能力（`D.positions[].abilities`） | **去重**：被多个岗位要求时只列一次，所有相关岗位都连过来 |

- 列头格式同行业全景：「行业」「专业 3」「岗位 9」「能力项 28」。
- **能力行**：圆点（核心能力为品牌色，其余为灰色）+ 能力名 + ★（核心能力）+ 右侧「×N」。N = 本树范围内要求这条能力的岗位数。
- **岗位节点**：右侧显示该岗位要求的能力数。
- **专业节点**：右侧显示对口岗位数，外加一个小「i」按钮（查看专业详情）。
- **能力排序**：沿用行业全景的做法，按所连岗位的平均高度排，尽量减少交叉。
- **不显示**：对口度标签（核心对口 / 相关）、「通用」标签、岗位 / 课程切换。

### 3.2 交互

| 操作 | 结果 |
|---|---|
| 悬停岗位 | 高亮它的连线、所属专业、它要求的全部能力，其余变淡 |
| 悬停能力 | 高亮所有要求它的岗位及连线 |
| 点岗位 | 右侧打开「岗位详情」；树上该岗位保持选中态 |
| 点能力 | 右侧打开「能力详情」 |
| 点专业的「i」 | 右侧打开「专业详情」（点专业卡片本身无反应） |
| 点行业 | 无反应 |

树上悬停提示的内容、选中栏（`#selBar` 那种）是否需要，参照行业全景自行判断，但不要显示第 5 节列出的字段。

## 4. 右侧详情面板

### 4.1 面板通用规则

- 从右侧滑出，宽度约为屏幕一半（窄屏占满）。有遮罩，点遮罩、「✕」或按 Esc 关闭。
- **详情里凡是节点名称都能点**，名称下加虚线下划线提示可点。点了在面板内打开该节点的详情，左上角出现「←」逐级返回。返回后，上一层的状态（能力 / 任务切换、展开 / 收起）要保留。关闭面板时清空返回栈。
- **归属链**：凡是写「来源」或「归属」的地方，一律写成可点的链：**专业 › 课程 › 任务 › 流程**（跳过模块层；没有流程的写到任务为止）。链上每一段都能点开。**不要把节点自己放进它的归属链**：比如任务标题下只写「专业 › 课程」。
- **数量多时只展示一部分**，并写明「共 N 条，仅展示前 K 条」。K 值做成参数，默认值见各节。

### 4.2 岗位详情

1. **头部**：归属（行业 › 子行业）、岗位名、岗位职责；下方是切换「岗位下看：能力 N | 任务 N」，**默认「能力」**。
2. **范围**：这个岗位在树上连到的**所有专业**的课程内容，取并集。归属链里带出专业，所以不用再单独筛选专业。
3. **按能力**：
   - 每个能力一段，左侧圆点写要求等级（L1 / L2 / L3）。标题写能力名、★、所属领域、「岗位要求 Lx · 权重 w」、技能数。**默认只展开前 2 段**，其余点标题展开。
   - 段内列出「技能（能）」：默认前 3 条。每条技能写：技能名、「来源：」归属链（有多处出处时写「另 n 处」），下面缩进挂「知识点 n / 规范 n / 案例 n」，每类最多列 5 个名称，超出写「等 n 条」。
   - 这条能力没有任何技能时，写「这条能力目前没有教学内容支撑」。
   - 能力最多展示 6 段，其余用「共 N 个能力」提示。
4. **按任务**：
   - 列出和这个岗位相关的任务（即任务下有技能映射到该岗位要求的能力），按技能数从多到少排，默认前 5 个。
   - 每个任务一段：标题写任务名；副行写「归属：专业 › 课程」「n 个操作流程」「n 个技能」。默认展开前 2 段；未展开的段落在点开时再加载内容。
   - 段内按流程分组，每组标题「流程：xxx」（可点）。组内列技能（默认前 3 条），每条技能写一行「能力 xxx」（可点），下面挂知识点、规范、案例。
   - 没有流程层的任务：写「以下内容直接挂在任务下」。
   - 流程下没有技能命中能力时：写「没有技能命中能力项，以下知识点 / 规范 / 案例直接挂在流程下」，然后直接列三要素。

### 4.3 其他节点详情

| 节点 | 内容 |
|---|---|
| 专业 | 归属（行业）；对口岗位列表；课程列表（前 10 门） |
| 能力 | 归属（行业 › 能力领域）、★ 核心能力、定义、L1–L3 三级要求、要求它的岗位（带等级）、支撑技能（前 6 条，带来源归属链） |
| 课程 | 归属（行业 › 专业）、课程类型、描述、任务列表（前 10 个） |
| 任务 | 归属（专业 › 课程）、任务结果；按顺序列出操作流程；没有流程层时直接列技能 |
| 流程 | 归属（专业 › 课程 › 任务）、流程结果；技能，每条带「能力 xxx」和下挂的知识点、规范、案例 |
| 技能 | 归属链（列出全部出处）、说明、对应能力、下挂的知识点、规范、案例 |
| 知识点 / 规范 / 案例 | 归属技能、内容说明、所在位置（归属链） |

## 5. 口径与不展示的内容

- **技能 → 能力**：只取「完全 / 部分对应」的映射（具体取值以第 2 节探索结果为准），和能力测评口径一致。映射都是已确认数据，不做审核状态区分。
- **知识点、规范、案例挂在技能下**是目标结构。如果第 2 节确认数据里它们还挂在流程、步骤或任务下，**过渡做法**是：取技能所在的最近上级（步骤 → 流程 → 任务）下的三要素，挂到该技能下显示。这样同一流程下多个技能会显示相同内容，这一点要在回报里写明。三要素重新挂载到技能之后，改为只取技能直属的。
- **页面上一律不显示**：
  - 映射关系类型（直接支撑等）、覆盖度、置信度、主归属 / 次要关联；
  - 对口度标签（核心对口 / 相关）、「通用」标签；
  - 岗位 / 课程详情头部的数据汇总标签行（如「映射到 381 个技能」「来自 21 门课程」等一排数字）；
  - 任何院校或测评数据：全景图谱是参照体系，不代表本校现状。
